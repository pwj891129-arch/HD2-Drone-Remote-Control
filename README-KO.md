## 0.2.22 Q+G 진입과 폭발 후 외형 수정

- 가드 독 배낭이 없거나 다른 배낭을 사용했을 때 배낭 판독 실패가 씨커 단축키 이력을 매 프레임 지우던 경로를 수정했다.
- 빠른 투척 중 실제로 생성되는 본인 씨커를 최대 3초 기다린다. 인벤토리 항목과 캐릭터에 붙은 동일 객체만 추적한다.
- 실제 투척 기록에서 `상태 2 → 상태 4`, 자동 이동 활성화가 확인됐다. 상태 3만 기다리던 조건을 3·4로 수정했다.
  손에 붙은 상태, 자동 이동이 꺼진 상태, 다른 소유자·재사용 객체에는 진입하지 않는다.
- 폭발 직후 드론 AI·이동·회전 제어를 해제해 원래 폭발 후 정리가 진행되도록 한다.
  폭발한 동일 씨커의 외형만 숨기며 피해·이펙트·원래 파괴 함수는 변경하지 않는다.
- **카메라만 0.7초 유지**한 뒤 플레이어 시점·입력을 복원한다. 추가 폭발 입력이나 파괴된 객체 조종은 하지 않는다.

오프라인 회귀 검사 통과. 현재 게임에는 읽기 전용 확인만 했으며 수정판 자동 설치·입력 전송·폭발 호출은 하지 않았다.
게임을 완전히 종료하고 **0.2.22 ZIP 한 개로 교체·적용**한 뒤 Q+G 진입과 폭발 장면을 확인한다.
이번 수정판의 실제 동작 확인은 아직 필요하다.

## 0.2.21 빠른 투척 진입과 폭발 장면 유지

- 씨커를 4번으로 손에 들지 않아도 **조준 모드 전환 키를 누른 채 빠른 투척 키(현재 Q+G)**를 사용해 조종을 준비한다.
  두 키 모두 게임 설정에서 읽으며, 빠른 투척 키가 없거나 지원하지 않는 장치에만 연결돼 있어도 기존 배낭·Q+공격 기능은 막지 않는다.
- 본인 인벤토리의 투척무기 항목과 캐릭터에 붙은 동일 씨커만 예약한다. 실제 게임의 투척·전개를 기다리고
  공격·투척 키를 놓은 뒤 조종한다. 근처에 날아가는 드론을 임의로 선택하거나 G를 대신 입력하지 않는다.
- 빠른 투척 예약 순간 객체가 아직 없으면 최대 1초 동안 본인 항목에서만 기다린다. 확인하지 못하면 원래 투척을 방해하지 않고 취소한다.
- 기존 **4번으로 손에 들기 → Q+공격 → 공격키 놓기** 방식은 유지한다.
- 폭발 요청이나 원본 폭발 상태를 확인하면 마지막 카메라 위치·각도를 **0.7초 고정**해 폭발 장면을 본 뒤 플레이어 시점·입력을 복원한다.
  드론 객체가 파괴돼도 유지 중에는 드론 위치·무기·AI를 다시 판독하거나 조종하지 않는다. 추가 공격·Q 입력도 다시 폭발시키지 않는다.
- 포커스 상실, 파티원 합류, 소유자·카메라·입력 설정 변경, 모드 종료 시에는 유지시간을 기다리지 않고 복원을 시도한다.
  배낭 드론의 과열·탄 소진 종료에는 이 지연을 적용하지 않는다.

실행 중인 게임의 빠른 투척 액션 `0x20015`에 G 키 값이 보존된 것을 읽기 전용으로 확인했다.
Q+빠른 투척, 늦게 생성된 본인 객체 대기, 다른 객체 거부, 객체 파괴 후 카메라 유지,
새 카메라 요청으로의 인계와 조기 종료·복원을 오프라인 검증했다.
**실제 Q+G 진입과 폭발 장면 유지 타이밍은 새 ZIP 적용 후 확인해야 한다.**
게임에는 메모리 쓰기·입력 전송·폭발 함수 호출·자동 설치를 하지 않았다.

게임을 완전히 종료하고 기존 드론 ZIP을 **0.2.21 한 개로 교체·적용**한 뒤 재시작한다.
솔로에서 씨커를 장착한 상태로 Q+G를 사용하고 실제 전개 후 조종되는지 확인한다.
조종 중 공격키나 Q를 새로 눌러 폭발시킨 뒤 약 0.7초 후 정상 시점·이동이 돌아오는지도 확인한다.
로그의 `seeker explosion view`는 카메라 유지 단계, `exit`는 복원 종료 사유다.

이 버전은 읽기 전용 진단이 아니라 **실제 제어 경로를 연결한 솔로 가드 독 배낭·투척 씨커용 프로토타입**이다.
0.2.11의 키보드 이동은 사용자 테스트로 확인됐지만 이번 변경의 실기 안정성은 확인 전이다.
기존 0.1.0 ZIP은 API 이름만 기록하는 진단판이며 원격조종 기능이 없다.

## 0.2.20 투척 씨커 조종

0.2.19에는 투척 드론 조종 경로가 없었다. 이번 판에서 **G-50 씨커·G-60 대전차 씨커**를 연결했다.
파티원이 없는 솔로에서만 사용하며 가드 독 배낭 5종 지원도 유지한다.

1. 투척무기 들기 키(현재 4번)로 씨커를 손에 든다. 일반 빠른 투척 G 입력은 조종 진입으로 취급하지 않는다.
2. **Q(게임의 조준 모드 전환 키)를 누른 채 공격키를 누른다.** 이 시점에는 대상만 예약하고 캐릭터·카메라·드론 AI를 변경하지 않는다.
3. **공격키를 놓아 실제로 던진다.** 별도 투척 입력을 보내지 않으며, 손에 들었던 정확히 같은 객체가 공중에 전개된 뒤에만 조종한다.
4. 기존 드론처럼 이동키로 전후좌우, 회피키로 상승, 앉기키로 하강하며 마우스로 카메라·본체 방향을 바꾼다.
5. 조종 중 공격키를 새로 누르거나 Q를 놓았다가 다시 누르면 **원래 씨커의 폭발 처리**를 요청하고 카메라·입력을 복원한다.

- 던질 때 공격키를 놓는 입력과 계속 누르고 있던 Q는 폭발 입력으로 다시 사용하지 않는다.
- 전개 확인 후 **30초**가 지나면 같은 원본 폭발 처리를 요청한다. 화면 높이 70%에 남은 시간과 거리를 표시한다.
- 씨커는 **복귀 기능·100m 거리 제한이 없다**. 일반 배낭 드론의 100m 제한과 탄 소진 복귀는 그대로다.
- 표면과 **0.5m 비물리 이격**을 사용한다. 모드가 벽 근접이나 충돌을 폭발 조건으로 추가하지 않는다.
- 캐릭터 몸 회전값은 변경하지 않는다. 가드 독의 자동조준 옵션은 씨커에 적용하지 않으며 씨커의 원래 AI·Boids를 조종 중 잠시 중지한다.
- 파티원 합류·객체 교체·포커스 상실·오류 종료 시 추가 폭발을 요청하지 않고 제어권을 원래 동작에 반환한다.
- 손에서 떨어지지 않은 투척 대기는 8초 후 취소하며, 들고 있는 폭탄을 강제 투척하거나 폭발시키지 않는다.

현재 게임에서 G-60의 손에 든 객체·슬롯 4·솔로 상태·원본 AI 타입 4·수납 상태 1·
카메라·이동·폭발 컴포넌트 연결과 폭발 함수 코드 가드 3곳을 **읽기 전용**으로 확인했다.
손에 든 상태의 폭발 허용 검사는 거부되는 것이 정상이며 실제로 거부됐다.
기존 투척 자료에서 공중 상태 3·부모 해제·Boids 활성화도 확인했다.
실제 투척 시 같은 객체를 계속 추적하는 전체 경로, Q/공격/시간 종료, 입력·카메라 복원,
다른 객체·세대·부모·파티 변경 차단과 코드 가드 실패는 오프라인 검증했다.
게임에는 메모리 쓰기·입력 전송·폭발 함수 호출·새 ZIP 설치를 하지 않았다.
**실제 씨커 카메라 전환·이동·폭발·0.5m 이격과 네이티브 호출의 안정성은 새 ZIP 적용 후 시험해야 한다.**
기존 드론의 정밀 조준점·이펙트 문제까지 해결한 판은 아니다.

게임을 완전히 종료하고 기존 드론 ZIP을 **0.2.20 한 개로 교체·적용**한 뒤 재시작한다.
먼저 적이 없는 넓은 방향으로 짧게 던지고 이동한 뒤 Q를 새로 눌러 종료·폭발을 확인한다.
로그의 `seeker armed`는 투척 예약, `entered G-60 ANTI-TANK SEEKER remote control`은 조종 진입,
`seeker_manual_detonation` / `seeker_time_expired`는 종료 사유다. 실제 폭발 성공을 로그만으로 확정하지 않는다.
자동 설치·GitHub 게시·헬퍼 변경은 하지 않았다.

## 0.2.19 가드 독 배낭 5종 지원

로버 전용 제한을 종류별 배낭→본체→탑재 무기 검사로 교체했다.
지원 대상은 일반 가드 독, 레이저 가드 독 로버, 핫 독, K-9, 독 브레스다.
알 수 없는 배낭이나 개조된 무기는 추측해서 연결하지 않는다.
가까운 드론을 고르는 방식이 아니라 현재 착용한 배낭의 소유한 드론만 제어한다.

- 로버는 실제 발열·완전 과열·예비 방열판을 표시한다.
- 나머지 네 종류는 실제 탄창 잔량과 예비 탄창을 표시한다. 탄창이 0이어도 마지막 약실 탄이 남으면 소진으로 처리하지 않는다.
- 탄 소진이나 과열 시 수동 사격을 해제하고 카메라·입력·비행·AI를 복원한다. 원래 드론 AI에 복귀·재장전을 맡기며 탄약을 강제로 채우지 않는다.
- 드론마다 다른 원본 AI 타입을 사용한다. 일반 가드 독 191, 핫 독 188, 독 브레스 189, 로버·K-9 190이다.
- 수동 사격 중 원본 AI 타입으로 재개되는 경우에도 해당 종류의 값만 인정한다. 다른 AI 값은 덮어쓰지 않는다.
- 파티원이 없는 솔로에서만 진입한다. 조종 도중 파티원이 합류하면 종료·복원을 시도한다.
- 기존 회수→수납 확인→전개 순서, 관성, 표면 이격, 100m 거리 제한과 동반 헬퍼 협력을 유지한다.

2026-10-09 실행 중인 게임에서 일반 가드 독의 배낭·본체·무기 소유권,
탄창·예비 탄창, 원본 AI 191, 카메라·비행·사격 연결을 읽기 전용으로 확인했다.
다섯 종류의 원본 AI 타입은 같은 게임의 로드된 드론 정의와 대조했다.
이 검사는 게임 메모리 쓰기·입력 전송·엔진 함수 호출을 하지 않았다.
종류별 판독·잘못된 무기 거부·탄 소진·AI 복원·파티원 합류 종료를 오프라인 검증했다.
**추가 네 종류의 실제 원격 이동·카메라·사격과 자동 복귀는 새 ZIP 적용 후 시험해야 한다.**
로버의 기존 조준점·이펙트와 표면 회피의 한계도 이번 확장으로 해결됐다고 주장하지 않는다.
**0.2.19에는 투척용 G-50/G-60 씨커 원격조종이 포함되지 않았다. 0.2.20에서 추가했다.**

게임을 완전히 종료하고 기존 드론 ZIP을 0.2.19 한 개로 교체·적용한 뒤 재시작한다.
먼저 일반 가드 독으로 Q+T(현재 사용자 설정)를 누르고 두 키를 놓아 진입한다.
카메라 전환→짧은 이동→수동 사격→T 종료 순으로 확인한다.
`entered GUARD DOG remote control`은 새 종류의 진입 기록이며 `ammo_empty_return`은 탄 소진 종료 사유다.
연결 검사 통과나 이 로그만으로 실제 이동·사격 성공을 확정하지 않는다.
자동 설치·GitHub 게시·헬퍼 변경은 하지 않았다.

## 0.2.18 비물리 표면 이격

물리 충돌체나 반발력을 추가하지 않고 **드론 중심과 벽·지면·천장 사이 약 1m**를 유지하도록 이동 명령을 보정한다.
게임 내부 박스 스윕을 작은 가상 센서로 사용하며 조회 결과는 모드 전용 버퍼에만 받는다.
공유 작업 큐·지형·물리 충돌체·캐릭터 회전값은 변경하지 않는다.

- 기본 조회 간격은 50ms이며 주변 6방향과 필요할 때 이동 방향을 추가한다. 한 번에 최대 7회, 범위 4m다.
- 이동 방향이 크게 바뀌거나 드론 위치가 갑자기 변하면 캐시를 새로 검사한다.
- 표면 접근 속도를 점차 줄이고 벽을 따라 움직이는 성분은 유지한다.
- 이미 너무 가까운 경우에는 초당 최대 2m의 완만한 후퇴를 요청한다. 순간이동이나 충돌 튕김은 사용하지 않는다.
- 좁은 틈에서 양쪽 1m 확보가 불가능하면 서로 반대 방향의 밀어내기를 중단하고 평행 이동을 유지한다.
- 조회가 일시적으로 불가능하거나 결과가 잘못되면 이동을 멈추고 HUD에 `SURFACE WAIT`를 표시한다.
  사격·카메라 회전·T 종료는 유지하며 정상 판독 후 이동을 다시 허용한다. 실패 재시도도 50ms 간격이다.

2026-10-09 함선에서 실행 중인 게임의 함수 바이트 10곳·API 테이블·세계 연결을 읽기 전용으로 확인했다.
조회 스케줄러는 20회 판독 모두 완료 상태였다. 이 검사는 게임 값을 쓰거나 게임 함수를 실행하지 않았다.
거리 보정·관성·경사면·모서리·좁은 틈·판독 실패/복구·이동/카메라 동기화·기존 종료 복원을 오프라인 검사했다.

솔로 로버를 꺼내 Q+T(현재 사용자 설정)로 진입하고 두 키를 놓는다.
먼저 사격 없이 평평한 지면·넓은 벽에 천천히 접근하고, 벽을 따라 옆으로 움직여 본다.
`surface clearance: ready`는 조회 성공, 다른 이유는 이동 대기의 원인이다.
T 종료 후 캐릭터 이동과 시야도 확인한다. 자동 설치·GitHub 게시·헬퍼 변경은 하지 않았다.

정확한 조준점 일치·공격 이펙트·지면·벽 충돌은 이번 수정으로 완성됐다고 주장하지 않는다.

## 0.2.14 실시간 모델 조준 및 발사 방향 연결

0.2.13은 Targeting의 목표점만 변경하고 몸체에 카메라의 좌우·상하 회전을 적용했다.
하부 총기의 모델 조준 입력(LookAt)과 발사 입력은 게임의 별도 생산 경로에 의존했다.
새 수동 조준은 발사 여부와 관계없이 그 두 입력도 매 조종 프레임 갱신한다.
동일한 지연된 목표점을 Targeting·LookAt·발사 슬롯 0에 보내며 무기 위치를 기준으로 방향을 계산한다.
입력 주소는 소유한 로버의 구성요소·세대·로컬 소유권·배열 신원으로 검증한다.
전역 코드 수정이나 새 네이티브 함수 호출은 추가하지 않았다.

카메라는 마우스에 즉시 반응하고 조준 방향은 **초당 180도**까지 따라온다.
90도 전환은 약 0.5초, 180도 전환은 약 1초이며 프레임 속도와 관계없이 계산한다.
이 지연은 사격하지 않을 때도 적용하며 모델과 발사 입력에 함께 사용한다.
몸체에는 좌우 회전만 적용하고 하부 무기의 상하 회전은 원래 LookAt의 모델 노드 처리를 사용한다.
자동조준 ON에서는 기존 적 추적을 유지한다. 이번 수동 조준 테스트는 **자동조준 OFF**로 진행한다.

LookAt와 발사 입력은 원래 엔진이 매 프레임 생산하는 일시적인 값이다.
조종 종료 시 이전 좌표를 덮어쓰지 않고 자동 표적 모드를 복원해 엔진이 다시 생산하게 한다.
부분 실패 시 공격을 중단하고 모드·카메라·캐릭터 입력을 복원한다.

회전 속도·발사 없는 조준·상하/반대 방향·같은 목표점 전달·오류 복원은 오프라인 검증했다.
**게임에서 몸체·하부 총기·이펙트·실제 명중이 일치하는지는 새 ZIP 적용 후 확인해야 한다.**
목표는 여전히 카메라 100m 앞이므로 표면까지의 정확한 거리 검사가 필요한 근거리 오차는 남을 수 있다.
안전한 표면 raycast가 확인되지 않아 정확한 근거리 명중이나 지면·벽 충돌 완성을 주장하지 않는다.

게임 종료 후 기존 드론 ZIP을 최신 0.2.17로 교체하고 적용·재시작한다.
먼저 공격하지 않고 마우스 좌우·상하 회전을 확인한 뒤 같은 방향으로 지속 공격을 시험한다.
새 모드는 자동 설치하거나 게시하지 않았다. 헬퍼 모드의 실제 소스·배포 ZIP은 변경하지 않았다.

## 0.2.13 자동조준 옵션 및 수동 표적 처리

인게임 `MODS > 드론 원격조종 > 자동조준`에 ON/OFF 토글을 추가했다.
기본값은 **OFF**이며, 변경 즉시 적용하고 Mod Options Menu가 설정을 저장한다.
게임 텍스트 언어가 한국어이면 옵션도 한국어, 그 밖의 언어는 영어로 표시한다.
언어를 바꿨다가 한국어로 돌아와도 다음 메뉴 표시에서 현재 언어를 읽는다.
옵션 변경에는 **Bingus Mod Options Menu v1.2 / API 1 version 3 이상**이 필요하다.
옵션 메뉴가 없으면 원격조종은 기본 수동 조준으로 작동한다.

OFF: 조종 중 적 탐색을 중지하고 카메라 앞의 조준 좌표를 로버의 Targeting 처리에 전달한다.
발사 여부와 관계없이 매 조종 프레임 갱신하며 원래 LookAt·발사 처리에서 사용하게 한다.
ON: 모드가 보관한 표적 값을 복원하고 게임의 적 추적을 사용한다.
자동 모드에서는 본체 회전을 카메라 값으로 강제 변경하지 않는다.
HUD의 `AIM MANUAL` / `AIM AUTO`로 현재 모드를 구분한다. 공격 입력은 두 모드 모두 수동이다.
조종 종료·오류 시 모드 소유 값만 복원하며 객체 교체·외부 값 변경은 덮어쓰지 않는다.

현재는 카메라의 100m 앞을 표적으로 사용한다. 표면 교차점 검사는 아직 없다.
따라서 카메라와 총구의 거리 차이 때문에 근거리에서는 조준점과 실제 명중점이 다를 수 있다.
**새 표적 연결·하부 총기 상하각·ON/OFF 실기 동작은 새 ZIP 적용 후 확인해야 한다.**
**지면·벽 충돌은 미완성이며 이번 버전에 완성됐다고 주장하지 않는다.**
Mover 종류 3의 추가 조사에서도 2D 동적 격자 회피 경로만 확인했고,
지형·벽 형상을 검사하는 안전한 sweep/raycast 호출은 아직 확인하지 못했다.

오프라인 옵션·표적·복원·컨트롤러 통합 테스트를 실행한다.
현재 실행 중인 로버의 표적 구성요소·원래 모드 0·코드 가드 21곳은 읽기 전용으로 확인했다.
이번 관찰 기록은 원격조종 상태가 아니라 일반 로버 상태이므로 새 조종 성공의 증거는 아니다.
실행 중인 게임에 새 코드 설치·메모리 쓰기·입력 전송은 하지 않았다.

## 0.2.12 관성·입력 차단·사격 시 종료 수정

이동키를 누르면 초속 8m까지 점진적으로 가속하고, 놓으면 잠깐 관성을 유지하며 감속한다.
가속은 초당 24m/s, 무입력 감속은 초당 16m/s이며 대각선에서도 최고속도는 같다.
시야를 돌려도 기존 관성은 월드 방향으로 유지하고 새 입력의 추진 방향만 바뀐다.
거리·열·방열판 HUD는 화면 아래에서 높이 70%인 중앙 위치에 표시한다.

캐릭터 이동·공격·마우스 시선 등 게임 동작은 조종 중 입력 개수를 0으로 비워 차단한다.
이전의 바인딩 표시값 0은 게임의 기본 장치 선택 경로에서 여전히 입력으로 해석될 수 있었다.
모드 내부에서는 원래 설정 키의 실제 눌림 상태를 계속 읽는다.
종료·오류 시 원래 입력 개수를 복원하며 설정표 교체나 외부 변경은 덮어쓰지 않는다.

드론 회전은 카메라와 같은 회전값으로 엔진의 즉시 회전 갱신 경로에 전달한다.
좌클릭 직후 조종이 끝나는 기존 기록에는 `control_behavior_resumed`가 확인됐다.
수동 사격 중 또는 해제 후 1초 안에 같은 로버의 행동값이 원래 값 190으로 돌아온 경우만
값 0으로 다시 확보한다. 자동 비행·무기·객체 신원이 유지될 때만 허용하며,
다른 행동값이나 사격 구간 밖의 재개는 여전히 조종을 종료한다.
새 회전·캐릭터 시선 차단·지속 사격 및 실제 피해는 ZIP 교체 후 실기 확인이 필요하다.

**지면·벽을 통과하지 않는 충돌 처리는 아직 구현하지 않았다.**
추가 코드 조사에서 로버의 현재 Mover 종류 2가 충돌 검사 없이 위치를 적분함을 확인했다.
종류 3의 검사 경로는 유효한 충돌 등록값이 필요하지만 현재 로버에는 그 값이 없다.
종류만 임의로 바꾸거나 다른 객체의 충돌 핸들을 가져오는 수정은 하지 않았다.
따라서 아래 0.2.11 설명의 '원래 이동 엔진이 충돌을 처리한다'는 내용은 잘못된 설명이다.
안전한 충돌 등록·검사 경로를 확인한 뒤 별도로 연결해야 한다.

입력 없이 대기 → W 이동·해제 → 마우스 회전 → 좌클릭 사격 → T 종료 순으로 시험한다.
게임 종료 후 기존 드론 ZIP을 0.2.12로 교체한다. 실행 중인 게임에는 적용하지 않았다.
자동 설치·GitHub 게시를 하지 않았으며 개인 솔로 로버 시험용이다.

## 0.2.11 한 방향 비행 및 이동 입력 수정

0.2.10에서는 빙글빙글 도는 현상은 사라졌지만 한 방향으로 계속 날아갔다.
게임 로그는 W의 눌림·해제를 감지했고 해제 후 계산 이동량은 0이었다.
읽기 전용 기록에서도 행동 AI와 자동 비행이 꺼져 있는 동안 좌표가 계속 이동했다.
단순한 키 눌림 고정 문제로 볼 수는 없다.

로버의 자동 비행 계산과 실제 이동 엔진(Mover)은 서로 다른 처리다.
현재 게임 코드에서 로버가 방향 3개와 속도 1개를 Mover에 전달하는 경로를 확인했다.
기존 코드는 이 입력을 비우지 않고 장면 유닛의 좌표만 변경하고 있었다.
0.2.11은 소유한 로버의 Mover 입력을 보관하고 진입 시 방향·속도를 0으로 비운다.
조종 중 게임에 설정된 이동·회피·앉기 키로 방향·속도를 전달하며,
키를 놓으면 이전 이동 속도가 남지 않도록 다시 0으로 보낸다.
장면 좌표를 강제로 옮기는 호출은 제거했고 이동 위치는 원래 이동 엔진을 사용한다.
이 경로가 충돌을 처리한다는 당시 설명은 0.2.12 조사에서 정정했다.
마우스 회전 및 드론·레이저 장면 갱신은 유지한다.

다른 드론의 입력이나 전역 이동 코드는 수정하지 않는다.
소유권·입력 배열·객체 세대가 바뀌면 조종을 중단하며,
다른 코드가 변경한 입력은 덮어쓰거나 원래 값으로 복원하지 않는다.
정상 종료 시 모드가 보관한 입력을 복원하고 자동 행동을 다시 활성화한다.

입력 없음·W 이동·키 해제 후 정지·각 방향·반대 입력 상쇄와 오류 복원을 오프라인 검증했다.
실행 중인 게임의 Mover 연결과 코드 14곳도 읽기 전용으로 확인했다.
새 버전의 실제 이동·회전·정지·사격은 아직 검증하지 않았다.
0.2.10의 좌클릭 후 `control_behavior_resumed` 종료는 별도 문제로 남아 있다.

게임 종료 후 이전 드론 ZIP을 교체하고 Q+T(현재 사용자 설정)로 진입한다.
먼저 입력 없이 대기 → W 이동 → W 해제 후 정지 → T 종료를 확인한다.
**자동 설치·실행 중 게임 변경·GitHub 게시는 하지 않았다.**

## 0.2.10 자동 비행 간섭 및 카메라 갱신 수정

0.2.9 실기에서는 카메라가 드론으로 전환됐지만 드론이 빙글빙글 이동했고,
좌클릭 직후 카메라가 플레이어로 돌아오는 현상이 있었다.
읽기 전용 기록에서 행동 AI가 0으로 중지된 동안에도 자동 비행 처리(Boids)는 켜져 있었고,
드론의 속도·좌표가 계속 바뀌었다. 행동 AI 중지만으로는 자동 비행이 멈추지 않았다.

현재는 소유한 로버의 Boids 업데이트 허용값을 조종 중에만 중지하고 종료 시 원래 값으로 복원한다.
이 값의 실제 소비 코드와 자료 배치를 현재 게임 빌드의 코드 바이트로 검증한다.
다른 드론이나 전역 이동 처리 코드를 수정하지 않으며 객체·소유권·자료 배열이 바뀌면 중단한다.

플레이어 카메라 요청은 원형 기록 배열의 다른 항목으로 갱신될 수 있다.
이전 버전은 항목 주소가 바뀌면 드론 연결 변경으로 취급했다.
현재는 같은 소유자·같은 카메라 관리자에서 나온 정상 요청만 새로 연결하며,
이전 항목을 복원한 후 새 항목 하나만 보관한다. 다른 캐릭터나 지원하지 않는 카메라는 가져오지 않는다.

추가 기록에서 좌클릭은 드론의 발사 입력과 발사 상태까지 전달됐다.
다만 곧 연결 검사에서 조종이 종료됐으므로 지속 사격이나 실제 피해가 확인된 것은 아니다.
발사 경로를 추측해서 별도 네이티브 함수로 우회하지 않고, 기존 검증된 입력 경로를 유지했다.
로그는 객체·루트 노드·행동 AI·자동 비행·카메라 변경을 구분한다.
이동 입력 변화는 진입당 최대 12회, 0.25초 이상 간격으로 기록하며 공격은 눌림·해제만 기록한다.

자동 비행 중지·복원, 오류 복구, 카메라 기록 교체·반복 순환·외부 변경을 오프라인 검증했다.
**0.2.10의 실제 이동·회전·레이저 사격은 새 ZIP을 적용한 뒤 확인해야 한다.**
게임 종료 후 이전 드론 ZIP을 교체하고 Q+T(현재 사용자 설정)로 이동·회전·공격을 확인한다.

## 0.2.9 첫 조종 프레임 충돌 수정

0.2.8은 회수·전개와 조종 진입까지 통과했지만 카메라가 이동하기 시작할 때 게임이 종료됐다.
실제 충돌 덤프는 엔진의 `Quaternion` 생성자 내부에서 잘못된 벡터 포인터를 읽은 오류다.
이 생성자는 축 벡터와 회전 각도를 받는데, 모드는 회전 성분 숫자 4개를 전달하고 있었다.
성분 4개를 받는 `Quaternion.from_elements(x, y, z, w)`로 교체했다.

이 API가 없으면 카메라·캐릭터 입력을 가져오기 전에 중단한다.
좌표의 유한값 및 단위 회전값을 이동 쓰기 전에 검사하고 회전을 먼저 생성한다.
첫 이동과 HUD의 엔진 호출 전후를 진입마다 한 번만 기록하며 매 프레임 기록하지 않는다.
기존 테스트의 느슨한 생성자 모형도 실제 축·각도와 성분 생성 API를 구분하도록 수정했다.
잘못된 성분·API 누락·생성 실패 시 부분 이동이 발생하지 않는지 오프라인 검증한다.

덤프에서 확인한 충돌 경로를 수정한 개인 시험판이다.
**0.2.9의 실제 안정성·카메라·이동·사격은 아직 검증하지 않았다.**
게임을 종료한 상태에서 이전 드론 ZIP을 교체한 뒤 솔로 로버로 확인한다.

## 0.2.8 입력 차단 API 수정

0.2.7 실기 로그에서 소유한 드론·레이저 검색과 회수·수납·재전개는 통과했다.
전개 완료 후 `entry/engine_handles`의 `focus_api_unavailable`에서 중단됐으며
`entered Rover remote control`에는 도달하지 못했다.
원인은 게임에 없는 `Window.keyboard_focus` / `set_keyboard_focus` API를 요구한 것이다.

조종 중에는 캐릭터 게임 동작 바인딩을 임시로 차단하고 원래 값과 입력표의 신원을 보관한다.
드론은 보관한 키 설정과 Windows의 실제 눌림 상태를 사용하므로 WASD·공격·배낭 키를 계속 읽는다.
마우스에는 헬퍼 휠에서도 사용하는 포커스·커서 API만 사용한다.
회수·전개 준비 중에는 캐릭터 이동·공격 바인딩을 차단하지 않는다.
조종 종료·포커스 상실·오류 시 원래 바인딩을 복원하고, 복원 쓰기가 실패하면 재시도한다.
입력표가 교체되거나 다른 코드가 수정한 값은 덮어쓰지 않는다.
다른 바인딩이 변경돼도 신원이 유지된 모드 소유 바인딩은 각각 독립적으로 복원한다.
Alt+Tab 상태에서는 마우스를 다시 잡지 않고 게임으로 돌아온 뒤 마우스 복원을 완료한다.

모드의 회수·전개 입력은 키 해제 요청 뒤 실제 눌림 상태가 해제된 것을 확인한다.
해제가 늦게 반영되는 동안 그 입력을 새 배낭 취소 입력으로 취급하지 않는다.
0.5초 안에 해제를 확인하지 못하면 중단하며 모드 소유 키를 놓는 정리를 재시도한다.

실행 중인 게임을 읽기 전용으로 확인해 Q=81, T=84와 게임 동작 바인딩 115개,
배낭 바인딩 4개의 신원을 검증했다. 새 입력 차단은 실행 중인 게임에 적용하지 않았다.
API 누락, 부분 진입 실패, 복원 실패·재시도, 외부 설정 변경 및 지연된 키 해제를 오프라인 검증했다.
**실제 카메라 전환·이동·사격은 새 ZIP 적용 후 확인해야 한다.**

## 0.2.7 객체 검색 및 수납 판정 수정

0.2.6 로그에서 Q+T는 감지됐지만 `entry/recall_prepare`의 객체 검색에서 중단됐다.
실제 게임의 엔진 객체를 읽어 보니 구성요소의 리소스 값과 엔진 유닛 리소스 값이 달랐다.
이전 드론 검색 값은 실제로 레이저 무기의 엔진 리소스였으므로 무기를 후보로 찾은 뒤
드론의 고유값과 다르다는 안전 검사에서 거부됐다. 약 22cm 좌표 차이도 다른 유닛을 비교한 결과였다.

현재는 소유한 객체의 엔진 리소스를 읽고, 엔진이 반환한 핸들의 세대 포함 UnitRef를 정확히 대조한다.
구성요소의 로버·레이저 확인과 소유권 검사는 별도로 유지하며 좌표로 다른 드론을 선택하지 않는다.
검색 로그에는 실제 후보의 UnitRef와 반환 타입도 기록한다.

수납된 로버를 읽기 전용으로 확인한 결과 드론→착용한 배낭→플레이어의 부모 연결이 있었다.
같은 수납 상태에서 거리는 1.548m였으므로 기존 1.2m 조건이 수납 완료를 막았다.
수납은 이 소유한 부모 연결로 판단하고, 레이저→드론 연결도 확인한다.
전개 후 드론의 부모 연결이 없어져야 조종을 시작하거나 이동할 수 있다.
부모 상대 좌표와 월드 좌표의 차이만으로 수납을 추측하지 않는다.

객체 리소스·세대·부모 포인터 교체, 잘못된 소유자와 레이저 연결, 실제 수납 거리 재현을 검증했다.
실행 중인 게임에는 메모리 쓰기·입력 전송·엔진 호출·새 코드 설치를 하지 않았다.
**객체 및 수납 연결의 읽기 전용 검증을 통과했으며, 카메라·이동·사격 성공은 적용 후 확인해야 한다.**

## 0.2.6 회수 후 조종

게임에 설정된 조준 모드 전환 키+배낭 기능 키를 누르고 **두 키를 놓는다**.
현재 사용자 설정은 Q+T이며 고정 키가 아니다.
공중의 로버는 배낭 기능으로 회수하고 수납이 확인되면 같은 기능으로 다시 꺼낸다.
이미 등에 수납한 상태라면 회수를 생략하고 전개부터 진행한다.
게임의 원래 전개 과정이 끝난 뒤 소유권·부모 연결·카메라·사격 연결을 확인해 조종권을 가져온다.
수납된 드론을 강제 분리하거나 등에 붙은 채로 이동시키지는 않는다.

준비 중에는 캐릭터 입력·카메라·AI를 변경하지 않는다.
배낭 키를 새로 누르면 준비를 취소하고, 조종 중 같은 키로 종료한다.
단계별 대기 제한은 8초이다. 포커스 상실·임무 전환·객체 변경·입력 실패 시 중단하고
모드가 누른 키와 임시 배낭 바인딩을 복원한다. 회수/전개 입력은 게임 설정 키를 사용한다.
0.2.6의 부모 상대 좌표·플레이어 근접 조건은 0.2.7의 소유한 부모 연결 검사로 교체했다.

0.2.5 실기 로그에서 로버 후보 1개와 판독 좌표가 약 22cm 달라져,
2cm 위치 일치 검사에서 카메라 전환 전에 진입이 막힌 것을 확인했다.
0.2.6은 엔진이 반환한 유닛의 세대 포함 UnitRef를 배낭 연결에서 읽은 값과 정확히 대조한다.
가까운 다른 드론을 고르는 방식이 아니며, 네이티브 주소로 Lua 유닛을 만들지도 않는다.
현재 빌드의 핸들 인코딩 코드와 세대·소유권을 확인하고 실제 월드 및 유효한 좌표도 검사한다.

회수·수납·전개·취소·시간 초과·키 해제 실패 및 객체 교체를 오프라인 검증했다.
실행 중인 게임에는 새 코드 설치·메모리 쓰기·입력 전송·엔진 호출을 하지 않았다.
새 회수 순서와 **실제 카메라·이동·사격은 검증 전**이다.
로그의 `preparation: phase=...`로 수납 또는 전개 대기에서 막혔는지 확인할 수 있다.

## 0.2.5 루트 노드 번호 수정

0.2.4 실기 로그에서는 꺼낸 로버 후보 1개를 찾았지만 위치가 일치하지 않아
`stage=entry/engine_handles`의 `unit_handle_unavailable`로 진입을 거부했다.
실행 중인 게임을 읽기 전용으로 확인한 결과 Lua 노드 번호 기준값은 **1**이었다.
엔진의 위치 조회·위치 변경·회전 변경 API는 인수에서 이 값을 빼서 내부 노드를 선택한다.
이전 코드의 노드 인수 0은 루트 노드가 아니라 내부 노드 -1을 가리키는 오류였다.

현재 기준값을 판독하고 코드 바이트 및 0/1 범위를 검증한 뒤, 같은 번호로
드론·레이저의 루트 좌표를 조회하고 드론의 위치·회전을 변경하도록 수정했다.
조종 도중 기준값이 달라지면 이동하지 않는다. 소유권·위치·부모 연결 검사는 완화하지 않았다.
검색 로그에는 노드 번호, 기대 좌표, 가장 가까운 후보 좌표와 오차도 남긴다.

0/1 기준값, 변경·누락·알 수 없는 기준값 및 코드 변경을 오프라인 검증했다.
실기 읽기 전용 검사는 객체·키·카메라·사격 연결과 기준값 1을 확인한 것이며,
**0.2.5의 실제 진입·시점·이동·사격 성공은 적용 후 확인해야 한다.**

## 0.2.4 좌표 판독 및 진입 진단

0.2.3 실기 로그에서 진입 요청은 감지됐지만 `stage=entry/engine_handles`의
`position_invalid`로 중단되는 것을 확인했다. Q+T 미감지가 아니라 엔진 핸들 준비 단계의 실패다.
다만 기존 오류만으로 좌표를 반환한 후보나 잘못된 성분의 원인을 확정할 수는 없다.

엔진 벡터를 즉시 Lua 숫자 배열로 복사하고, 숫자형 네이티브 성분을 정규화한다.
자원별 검색에서는 좌표를 읽을 수 없거나 유효하지 않은 후보만 제외하고 나머지를 탐색한다.
정확한 객체 ID의 좌표가 틀리거나 여러 후보가 같은 위치로 일치하면 여전히 진입을 거부한다.
소유권·현재 월드·생존·위치·부모 연결 검사는 완화하지 않았다.
로그에 검색 경로, 후보 수, 잘못된 좌표 수와 해당 성분 오류를 추가했다.
거리 HUD 텍스트 좌표도 레이어가 있는 Vector3로 수정했다.

잘못된 후보, 네이티브 숫자, 중복 후보, 잘못된 정확 ID를 모의 테스트했다.
실제 게임에서 0.2.4의 진입·시점·이동·사격이 성공했는지는 아직 확인하지 않았다.

## 0.2.3 진입 키 변경

게임에 설정된 **조준 모드 전환 키 + 배낭 기능 키**로 진입한다.
조준 모드 전환 키를 먼저 누른 채 배낭 기능 키를 새로 누른다.
조종 중 배낭 기능 키를 놓았다가 다시 누르면 종료하며 조준 모드 전환 키는 필요하지 않다.
스트라타젬 키 조합과 기본 스트라타젬 목록의 열림 조건은 제거했다.
키보드·마우스 키의 실제 설정을 읽으며 기본 마우스 가운데 버튼으로 고정하지 않는다.
조준 모드 전환 키가 없거나 지원하지 않는 바인딩이면 진입을 거부하고 로그에 기록한다.
일반 배낭 기능, 휠·자동장전 협력과 기존 조종·복구 경로는 유지한다.

## 0.2.2 진입 오류 수정

실기 로그에서 단축키 처리 후 `unit_handle_unavailable`로 조종 진입이 실패하는 것을 확인했다.
0.2.1의 `tostring(Unit.resource_name(...))` 문자열 비교를 제거했다.
배낭 연결에서 검증한 드론·레이저의 게임 객체 ID로 `UnitSynchronizer`의 엔진 핸들을 조회한다.
동기화 조회가 제공되지 않는 유닛은 `IdString64.from_hex`와 `World.units_by_resource`로 검색한다.
두 경로 모두 실제 위치·생존·현재 월드와 수납 여부를 확인하며, 모호한 후보는 거부한다.
네이티브 포인터를 Lua 유닛 핸들로 변환하지 않는다.

이 엔진 API의 역할은 [Autodesk UnitSynchronizer 참조](https://help.autodesk.com/cloudhelp/ENU/Stingray-Help/lua_ref/obj_stingray_UnitSynchronizer.html)와
[World 참조](https://help.autodesk.com/cloudhelp/ENU/Stingray-Help/lua_ref/obj_stingray_World.html)에 설명되어 있다.
HD2의 실제 핸들 반환과 카메라·비행·사격 성공은 이번 ZIP 적용 후 별도로 검증해야 한다.

업데이트 인수의 첫 값이 항상 0.1초 이하라고 가정하던 검사도 제거했다.
엔진의 단조 시간값(없으면 Windows 단조 시간값)으로 이동 시간을 계산하고 50ms로 제한한다.
시작·일시정지·시간 초기화에는 이동량을 0으로 하며, 긴 로딩 프레임 때문에 조종을 거부하지 않는다.
진입 실패와 임무 전환 후에는 누른 키를 다시 놓아야 재진입한다.
로그의 `stage=`로 객체 판독·핸들 조회·입력 캡처·이동·사격·HUD 실패를 구분한다.

## 설치 및 첫 시험

1. 게임을 종료한다. 실행 중인 게임에 덮어쓰거나 외부에서 코드를 주입하지 않는다.
2. Arsenal에서 이전 드론 ZIP을 새 `Drone-Remote-Control-0.2.20-private-test-KO.zip` 또는 EN ZIP 하나로 교체한다.
3. 배낭·씨커 원격조종 옵션을 켜서 적용한다. Bingus Shared Loader API 1은 별도로 필요하다.
4. 함께 사용할 휠·자동장전은 입력 API 1을 제공하는 0.3.53-test 이상을 사용한다. 드론 모드와 휠·자동장전 옵션은 모두 켜 둘 수 있다. 이전 드론판을 동시에 설치하지 않는다.
5. 솔로 임무에서 지원하는 가드 독 배낭 5종 중 하나를 착용한다. 공중에 꺼냈거나 등에 수납된 상태 모두 준비를 시작할 수 있다.
6. 조준 모드 전환 키를 먼저 누른 상태에서 배낭 기능 키를 누르고 두 키를 놓는다. 회수·수납 확인·재전개가 끝날 때까지 기다린다.
7. 배낭 키를 놓았다가 다시 누르면 종료한다. 종료할 때 조준 모드 전환 키는 필요하지 않다.

실행 로그: `%LOCALAPPDATA%/CowboyBingus/Helldivers2/Logs/DroneRemoteControl.log`.
투척 씨커 시험은 위 0.2.20의 Q+공격→공격 해제 순서로 진행한다. 배낭용 Q+T는 씨커에 사용하지 않는다.
진입 거부 사유도 기록한다. 자동 설치와 온라인 게시는 하지 않았으며 개인 시험 ZIP만 생성한다.

## 휠·자동장전 함께 사용

0.2.1은 드론 진입 전에 휠을 닫고 미완료 커맨드·선택을 취소한다.
휠의 마우스 포커스와 모드가 누른 방향·목록·장전 키의 해제가 확인되어야 조종을 시작한다.
조종 중에는 휠·숫자 핫키·자동장전·레일건/에포크 자동발사를 잠시 멈춘다.
종료·진입 실패·포커스 상실 시 드론의 입력·AI·카메라 복원이 끝난 뒤 동반 모드를 재개한다.
복원 실패로 정리가 남아 있으면 동반 모드를 계속 멈추고 재시도한다. Arsenal 옵션값은 바꾸지 않는다.

조종 종료 후 공격키와 스트라타젬 키를 놓아야 한다. 휠 토글 방식은 기본 스트라타젬 목록도 닫은 뒤 새로 연다.
기존 선택이나 누른 채 남아 있는 숫자·공격키는 자동 실행하지 않는다. 엄지버튼의 누락된 해제 복구는 드론 포커스 복원이 끝난 뒤 처리한다.
입력 API 1이 없는 이전 휠·자동장전이 켜져 있으면 조종 진입을 거부하고 로그에 `upgrade_companion`을 기록한다.
함께 설치하는 모드는 여전히 별개의 ZIP이다. 두 로드 순서와 입력 해제·재개는 모의 테스트 대상이며 실제 게임 검증을 대신하지 않는다.

## 연결한 제어

- 게임에 저장된 조준 모드 전환·배낭·이동·회피·앉기·공격 키를 판독한다.
- 키 조합을 감지한 뒤 두 키가 해제되면 원래 배낭 바인딩을 복원하고 회수·전개 입력을 보낸다. 조종 진입·종료 키의 중복 배낭 입력만 임시 차단한다.
- 원격조종 중 키보드와 마우스의 캐릭터 입력 포커스를 차단한다.
- 소유한 드론의 AI 디스패치를 임시 중지하고 실제 탑재 무기 트리거의 시작·종료 함수를 연결한다.
- 엔진이 반환한 유닛 핸들로 위치·회전을 갱신한다. 네이티브 주소를 Lua 유닛으로 캐스팅하지 않는다.
- 현재 플레이어 카메라 큐의 위치·회전을 임시 고정 시점으로 전환한다.
- 이동키로 수평 이동, 회피키로 상승, 앉기키로 하강한다. 시험 이동속도는 8m/s이다.
- 100m 초과 시 조종을 해제한다. 거리 색은 80m 이하 초록, 80m 초과 주황, 90m 초과 빨강이다.
- 화면 높이 70% 지점에 실제 거리·조준 모드와 발열/방열판 또는 탄창/예비 탄창을 표시한다. 미확인 과열 최대값이나 총알 수를 만들지 않는다.
- 완전 과열, 탄 소진, 파티원 합류, 객체·카메라 연결 변경, 포커스 상실 및 종료 시 사격 중지·AI·카메라·입력 복원을 시도한다.
- 기록한 객체와 값이 여전히 일치하는 경우에만 복원한다. 타 모드나 다른 객체가 덮어쓴 값은 보존한다.
- 복원 쓰기가 실패하면 다시 조종을 시작하지 않고 복원을 재시도한다.

## 실기 검증 필요

실제 이동 유지, 수동 조준 방향, 카메라 표시, 캐릭터의 스트라타젬 입력 자세,
드론 AI의 이동 보정 간섭 및 자동 복귀 동작은 **실기 검증 전**이다.
충돌 판정과 멀티 동기화도 확인하지 않았다. 장애물 없는 솔로 환경에서 짧게 이동하고 종료한다.
미확인 애니메이션 함수를 호출하지 않으며 새 스트라타젬 자세를 강제 생성하지 않는다.
로버의 자동 냉각·방열판 소모를 완전히 재현하지 않고 과열 감지 시 원래 AI에 제어를 돌려준다.
실탄·분사·전기 드론은 탄 소진 시 조종을 종료해 원래 AI에 맡긴다. 종류별 실제 자동 복귀·재장전은 시험 전이다.

진입 조건은 소유권·종류별 배낭/본체/무기 자원 식별·세대 포함 UnitRef·유효한 위치·비부모 루트 확인을 함께 사용한다.
배낭 연결 ID나 AI 상태 번호만으로 꺼냄 상태를 확정하지 않는다.
지원하지 않는 게임 바이너리나 객체 구조에서는 작동을 거부한다.
Lua `pcall`은 네이티브 접근 위반을 막지 못한다. 가드가 있어도 첫 시험의 충돌 위험은 남는다.

## 검증 및 개발 자료

오프라인 제어·복구·입력·엔진 모의 테스트와 합성 메모리 테스트를 실행했다.
0.2.2까지 게임에서 Lua 판독기의 객체·카메라·사격 슬롯·키 설정도 읽기 전용으로 검증했다.
0.2.3의 조준 모드 전환 액션은 같은 빌드의 보관된 게임 코드에서 확인하고 바이트 가드를 추가했다.
0.2.3 실기 로그에서 새 키 조합에 의한 진입 요청은 확인했으나 엔진 핸들 준비에서 실패했다.
0.2.4의 좌표 판독·후보 제외와 HUD 레이어 변경은 오프라인 검증했으며 실기 시험은 아직 하지 않았다.
0.2.5는 같은 게임 빌드의 엔진 코드와 현재 게임에서 확인한 노드 번호 기준값 1을 사용한다.
읽기 전용 사전 검사와 오프라인 테스트를 통과했지만 실제 원격조종은 아직 검증 전이다.
이 검증에서는 게임 메모리 쓰기·엔진 호출·입력 전송을 하지 않았다. 판독 통과는 조종 성공을 의미하지 않는다.
저장된 개인 메모리 스냅샷과 타 모드 소스는 ZIP에 포함하지 않는다.

`tools/read_drone_state.py`와 `tools/preflight.py`는 개발용 읽기 전용 도구이며 모드 실행 의존성이 아니다.

## 목표

- 게임의 조준 모드 전환 키 + 배낭 기능키 조합으로 준비를 시작하고 회수·수납·전개 확인 후 진입.
- 조종 중 배낭 기능키를 다시 누르면 종료. 조준 모드 전환 키를 함께 누를 필요는 없다.
- 게임에 설정된 키를 사용하며 기본 배낭 키인 숫자 5로 고정하지 않는다. Z는 진입·종료에 사용하지 않는다.
- 캐릭터 이동·공격 차단 및 스트라타젬 입력 자세 유지.
- 드론 3인칭, 전후좌우 이동, 게임에 설정한 회피 키로 상승 및 앉기 키로 하강.
- 조종 중 자율 공격 중지 및 게임의 공격 키로 수동 사격.
- 탄약 소진 시 복귀. 로버는 총알 대신 실제 발열·과열·예비 방열판을 표시.
- 플레이어로부터 100m 초과 시 연결 해제. 80m 이하 초록, 80m 초과 주황, 90m 초과 빨강.
- 종료·사망·임무 변경·포커스 상실 시 캐릭터, 카메라, AI를 복원.

## 입력 규칙

`src/control_hotkey.lua`에 새 입력 규칙을 구현했고 오프라인 테스트로 확인했다.
진입 요청 후 두 키를 놓아야 준비를 진행한다. 배낭 키를 계속 누르고 있으면 준비 대기하며,
계속 누른 입력으로 취소되지 않는다. 손을 뗀 뒤 다시 누르면 준비 취소 또는 조종 종료한다.
키 설정 변경이나 초기 로드 직후 이미 눌린 키로는 진입하지 않는다.
조준 모드 전환 키 없이 조종 중이 아닌 상태에서 누르는 배낭 키는 일반 배낭 기능으로 남긴다.
0.2.0에서는 배낭 수납 입력 차단과 런타임 진입·종료를 연결했다.

## 확인한 것

2026-10-07 로버 실기 읽기 전용 기록에서 배낭 → 드론 본체 → 레이저 무기의 연결,
각 유닛의 위치, 무기 발열·과열 및 예비 방열판을 확인했다.
배낭의 연결 ID는 수납해도 유지된다. 연결 ID 존재 여부나 플레이어와의 거리만으로
꺼냄 상태를 확정하면 안 된다. AI 상태 번호는 수납·자동 복귀·공격 등의 동작 중에도 변한다.
드론이 공중에 나와 있는데 이전 상태 번호로 돌아온 기록도 있으므로 배포 코드의 꺼냄 열거형으로 쓰지 않는다.

## 이전 진단 ZIP

`releases/Drone-Remote-Control-Probe-0.1.0-private-test-{EN,KO}.zip`

Arsenal에 영어 또는 한국어 ZIP 하나만 가져와 읽기 전용 옵션을 활성화한 뒤 적용한다.
Bingus Shared Loader API 1은 별도로 필요하며 ZIP에 포함하지 않는다.
게임을 다시 실행하고 함선 또는 임무에 진입하면 다음 로그에 노출된 엔진 API 이름을 기록한다.

`%LOCALAPPDATA%/CowboyBingus/Helldivers2/Logs/DroneRemoteControlProbe.log`

이 진단은 나열한 엔진 함수를 호출하지 않으며 메모리 쓰기, 입력 전송,
카메라 변경, 드론 AI 변경을 하지 않는다. 전역 `update`와 `shutdown`은 기존 호출과
인수·반환값을 보존해 연결한다. 기존 모드 오류를 숨기지 않는다.
API 존재 확인은 호출 규약이나 안전한 유닛 소유권 검증을 대신하지 않는다.
자동 설치·온라인 게시를 수행하지 않는다.

`tools/read_drone_state.py`는 개발 PC에서 사용하는 외부 읽기 전용 스냅샷 도구이며
ZIP 실행 의존성이 아니다. 저장된 메모리 자료와 타 모드 소스는 ZIP에 포함하지 않는다.
